# ADR-0005：采用文件提取器注册表

- 状态：已接受
- 日期：2026-08-15

## 背景

原扫描器直接根据文件后缀调用 Python、JavaScript 和 Markdown 解析函数。继续横向增加结构化文本、更多编程语言和科学数据格式，会让扫描核心与具体格式、可选依赖、错误处理和测试策略高度耦合。

## 决策

1. 建立只返回 `ExtractionResult` 的提取器协议；
2. 核心扫描器通过注册表选择内置和 Entry Point 提取器；
3. 提取器不能直接访问数据库，也不能修改项目文件；
4. 文件内部结构保存为有上限的 L1 Resource 节点；
5. 只有文件到文件关系自动聚合为跨概念 L2 关系；
6. 提取器 ID、版本和注册表签名进入文件节点，版本变化触发重新提取；
7. 科学格式的重量级库保持可选，缺少依赖时返回诊断而不使扫描失败；
8. 提取器角色形成确定性 L2 提示，人工 Semantic Overlay 最后应用。

## 结果

优点：

- 新格式不再修改主扫描循环；
- 核心保持零强制第三方运行时依赖；
- 文件内部结构可以被 Agent 定位和查询；
- 提取器失败采用 fail-open；
- 第三方格式支持可以独立发布。

代价：

- L1 节点数量增加，需要严格设置资源上限；
- 启发式代码解析不等于编译器或 LSP；
- 可选依赖造成不同环境的增强深度不同；
- 插件生态需要稳定协议版本和合同测试。
