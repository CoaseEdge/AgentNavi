# 开发路线

## 0.1：可运行架构基线（已完成）

- 外置项目注册表；
- SQLite 三层统一图模型；
- Git 感知文件扫描；
- Python、JavaScript、TypeScript、Markdown 物理依赖；
- 测试关系推断；
- 保守自动语义图；
- 外部语义命令协议；
- Codex / Claude Code Hook 适配；
- 上下文、影响、历史查询；
- Obsidian 单向投影；
- 全局 Hook / Skill 安装器；
- 标准库测试和 CI。

## 0.2：可靠增量与可重放任务历史

- 独立 JSONL 事件日志；
- 从事件日志完整重建 L3；
- 图谱 schema migration 框架；
- Git diff 驱动的语义增量输入；
- 文件移动与重命名身份继承；
- 任务失败、取消和中断的更精确状态；
- 敏感字段可配置脱敏；
- 索引预算和超时配置。

## 0.3：更深 L1 解析

- Tree-sitter 解析器插件；
- Go、Rust、Java、C#、PHP 等语言；
- API 路由、数据库表和配置键关系；
- 符号级节点和调用图；
- 写作引用、脚注、文献库；
- 视频时间线、素材和输出关系。

## 0.4：语义审查与人工校正

- 语义关系候选队列；
- 接受、拒绝、合并和重命名概念；
- 人工修正作为独立 Overlay，不污染项目仓库；
- 修正优先级高于自动推断；
- Obsidian 批注导入，但不直接编辑生成页；
- 置信度校准与关系衰减。

## 0.5：Context Service

- 本地 HTTP API；
- MCP Server；
- Agent 统一 `query / context / impact / history` 接口；
- 远程沙箱通过受控隧道访问；
- 权限按项目、路径和 Agent 隔离；
- Dispatcher 使用图谱进行上下文路由。

## 0.6：跨项目 Work Graph

- 跨项目同义概念识别；
- 项目间依赖和复用；
- 个人与组织级任务历史；
- “在哪里讨论过这个问题”查询；
- 决策、产品、代码、研究和写作资产联动。

## 评估指标

后续版本必须以可测量结果验证价值：

- Agent 首次有效修改前读取的文件数；
- 探索阶段 Token；
- 无关文件读取比例；
- 任务完成时延；
- 漏读必要文件率；
- 图谱错误关系率；
- L2 人工纠正率；
- 索引开销与收益比。

不能仅凭“图看起来更完整”判断系统有效。
